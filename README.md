# DNG Multi Frame Averager
Standalone Windows application for merging multiple DNG files into a single DNG.

This Windows tool stacks multiple DNG (RAW) images of a stationary subject, **combining sensor data to reduce random noise** and outputting a single DNG file.

You can enable **alignment** to compensate for positional shifts caused by handheld shooting (disabled by default).

- Output DNG files **can be opened directly in Adobe Camera Raw or Lightroom**
(Verified in test environments to ensure no "file may be corrupted" warnings appear)
- Supports four stacking methods with **outlier rejection** (e.g., for airplanes or cosmic rays)
- **Defective pixel correction** to reduce tiny white dots in dark areas (involves trade-offs)
- Supports **dark frame subtraction**
- Supports **alignment** (automatic/manual) and **aberration correction** (both disabled by default)
- Accepts both **Bayer DNG and Linear DNG** (including pixel-shift composite images)
- Accepts **both compressed and uncompressed DNG** files
- Default settings can be customized via an **.ini file**

## できること

| 項目 | 内容 |
|---|---|
| 入力 | Bayerモザイクを含むDNG / リニアDNG(RGBの揃った**ピクセルシフト合成画像**を含む)<br>圧縮・非圧縮どちらも可、8/16bit |
| 合成 | 加算平均 / シグマクリップ / ウィンザライズ(既定) / +欠陥画素補正 の4種から選択 |
| ダーク減算 | フォルダ内のキーワード一致ファイル、または1枚を指定 |
| 位置合わせ | 手持ち撮影のコマ間の並進ずれを補正(既定OFF。ONにすると出力はリニアDNG) |
| ビット深度 | 入力に自動追従(14bit/16bit等。固定値ではない) |
| メタデータ | グループ1枚目のDNGの内容をそのまま引き継ぐ |
| プレビュー | グループ1枚目のサムネイル/プレビューを引き継ぐ |
| 出力 | ロスレス圧縮DNG(既定)または非圧縮DNG |
| ノイズ低減効果 | 枚数nに対して理論上 1/√n |

ノイズが 1/√n に下がる原理上、**4枚で約1/2、16枚で約1/4、64枚で約1/8** になります。

## 環境構築(使うだけの人向け)

### 必要なもの

- **Windows 10 / 11 (64bit)**
- **`DNG Multi Frame Averager.exe` 本体のみ**

DLLやランタイムの追加インストールは不要です(静的リンクした単一実行ファイル)。
Python や Adobe DNG Converter も**実行には不要**です。

日本語や空白を含むフォルダ名・ファイル名にも対応しています。コンソールの
コードページ(日本語環境の既定はcp932)を変更する必要もありません。

### 導入手順

1. `DNG Multi Frame Averager.exe` を好きなフォルダに置く
2. 以上です

初回起動時に、exeと同じ場所へ設定ファイル
`DNG Multi Frame Averager.ini` が自動生成されます。

> **補足**: 撮影したRAW(NEF/CR2/CR3/ARW等)をDNGに変換する必要がある場合のみ、
> 無料の [Adobe DNG Converter](https://helpx.adobe.com/camera-raw/using/adobe-dng-converter.html)
> を別途インストールしてください。**圧縮設定は既定のまま(圧縮あり)で構いません。**

## 使い方

### 方法1: ダブルクリックして対話形式で進める(おすすめ)

exeをダブルクリックすると、6ステップの対話形式で設定できます。
**すべての質問は Enter を押すだけで既定値**になるので、迷ったら Enter を連打すれば
そのまま動きます。

```
[1/6] 入力フォルダ    … 処理したいフォルダを指定(ドラッグ&ドロップ可)
[2/6] ダーク減算      … するかしないか、どう与えるか
[3/6] 合成方法        … 5つから選択。続けて位置合わせと収差補正も選択
[4/6] 出力設定        … 出力先 / サフィックス / 圧縮方式
[5/6] 設定確認        … 内容を確認して [Y/n]
[6/6] 処理            … 進捗バーとノイズ低減効果を表示
```

処理が終わってもウィンドウは自動で閉じません。結果を確認してから
**Enter を押すと終了**します。

### 方法2: フォルダをドラッグ&ドロップ

フォルダをexeのアイコンにドラッグ&ドロップすると、そのフォルダが入力として
設定された状態で対話が始まります。

### 方法3: コマンドラインから

```bash
"DNG Multi Frame Averager.exe" "D:\撮影\連写" --method winsor --yes
```

コマンドラインで指定した項目は対話で聞かれません。`--yes` を付けると
すべての質問を飛ばして即座に実行します(バッチファイル向け)。

### 表示について

操作を促す説明文は**日本語のあとに英語**を併記しています
(English instructions follow each Japanese line)。
パス・数値・ファイル名など言語に依存しないものは併記していません。

### 処理中に表示されるノイズ低減効果

```
[08:58:15] ⚙️  合成 / Stacking: MEAN  (全フレームをそのまま平均)
              合成 / Stacking [██████████████████████]   11/11 (100%)
              1枚あたり / Single frame          79.66  ████████████████████████
              64枚合成後 / After stacking        9.96  ███
              ノイズ / Noise  1/8.00      S/N  +18.1 dB
              外れ値の棄却 / Rejected : 12910540 / 2925158400  (0.441%)
```

- **1枚あたり**: 同じ画素のフレーム間ばらつきから推定した、1枚のRAWが持つ
  ランダムノイズの標準偏差
- **N枚合成後**: 理論上どこまで下がるか(1/√N倍)
- **S/N**: 信号対雑音比の改善量。`10 × log10(枚数)` [dB]
- **外れ値の棄却**: 何画素サンプルを外れ値として捨てたか

| 枚数 | ノイズ | S/N改善 |
|---|---|---|
| 4枚 | 1/2.0 | +6.0 dB |
| 16枚 | 1/4.0 | +12.0 dB |
| 32枚 | 1/5.7 | +15.1 dB |
| 64枚 | 1/8.0 | +18.1 dB |

## フォルダの置き方

**2通りのどちらでも動きます。**

### A. 1カットぶんのフォルダを直接指定する

```
D:\撮影\連写カット\        ← これを指定
├── DSC0001.dng
├── DSC0002.dng
└── DSC0003.dng
```

サブフォルダが無ければ、指定したフォルダ自体を1カットとして処理します。

### B. 親フォルダを指定して複数カットを一括処理する

```
D:\撮影\2026-07-27\        ← これを指定
├── カット1\                ← 1グループ
│   ├── DSC0001.dng
│   └── DSC0002.dng
├── カット2\                ← 別グループ
│   ├── DSC0010.dng
│   └── DSC0011.dng
└── DSC9999.dng             ← 直置きのDNGは無視され、警告が出る
```

サブフォルダにDNGがあれば、そちらが優先されます。

### 入力にできるDNG

| 種類 | 対応 | 出力 |
|---|---|---|
| Bayerモザイクを含むDNG(通常のRAW) | ○ | Bayer DNG(位置合わせONならリニアDNG) |
| リニアDNG(デモザイク済み・RGB) | ○ | リニアDNG |
| **ピクセルシフト合成画像**(全画素にRGBが揃ったリニアDNG) | ○ | リニアDNG |
| 浮動小数点DNG | × | エラーを出してスキップ |

ピクセルシフト(センサーシフト・マルチショット)で撮影・合成された画像は、
1画素ごとにRGB3サンプルを持つリニアDNGとして保存されます。本ツールはこれを
そのまま入力にできます。1サンプルあたりの扱いはBayerと同じで、**同じサンプル位置の
コマ間の値**を見て合成するため、アルゴリズムの選び方も変わりません。

ピクセルシフト合成は「1回のシャッターで得られる解像感」を上げる技術で、
連写の加算平均は「ランダムノイズを下げる」技術です。目的が違うので併用でき、
ピクセルシフト画像を複数枚重ねればさらにノイズを減らせます。

> ピクセルシフト画像は1画素あたり3サンプルあるため、**一時ファイルはBayerの約3倍**に
> なります(45MP・64枚で約17.6GB)。空き容量にご注意ください。

### ルールまとめ

- グループ内のファイルは**ファイル名の自然順**でソートされ、**1枚目が基準**になります
  (自然順 = `DSC2.dng` < `DSC10.dng` のように数字を数値として比較)
- **メタデータ(Exif・カラーマトリクス・ホワイトバランス・レンズ情報)と
  プレビューはグループ1枚目のDNGに準拠**します
- DNGが**0枚または1枚**のグループはスキップし、警告を出します
- **今回指定したサフィックス**で終わるファイルは、再実行時に入力として取り込まれない
  よう自動的に除外されます。サフィックスを変えて再実行する場合は先に前回の出力を
  削除してください
- 1つのグループが失敗しても**バッチ全体は止まらず**、次のグループへ進みます

## 合成方法の選び方

| # | 名前 | 向いている場面 | 速度 |
|---|---|---|---|
| 1 | 加算平均 | 外れ値が無いと分かっている場合。理論上もっとも低ノイズ | 最速 |
| 2 | 加算平均＋シグマクリップ | 飛行機・宇宙線・突発的な輝点を除去 | 速い |
| 3 | **ウィンザライズ**(既定) | **最も割が良い**。棄却の代償が最も小さい | 遅い |
| 4 | ウィンザライズ＋欠陥画素補正(dpc) | 暗部の白点を減らしたい場合。**細部を削るリスクあり** | 遅い |
| 5 | 全部 | 4種の違いを見比べたい場合 | 4つ分 |

`5. 全部` を選ぶと、出力ファイル名の末尾にアルゴリズム名が付きます
(`_AVE_MEAN.dng` / `_AVE_SIGMA.dng` / `_AVE_WINSOR.dng` / `_AVE_DPC.dng`)。

### どれを選ぶべきか(実測にもとづく指針)

同じ連写を奇数コマ32枚・偶数コマ32枚に分けてそれぞれ合成し、その差分から
残留ノイズを測りました。両者は同じ固定パターンを持つため差分では相殺され、
**ダーク減算で固定パターンを消した後と同じ条件**での比較になります。

| 領域 | 1. 加算平均 | 2. シグマクリップ | 3. ウィンザライズ |
|---|---|---|---|
| 平坦部 | **6.875** | 6.946 (+1.0%) | 6.887 (+0.2%) |
| 暗部 | **8.518** | 8.629 (+1.3%) | 8.547 (+0.3%) |
| 全体 | **18.787** | 19.068 (+1.5%) | 18.849 (+0.3%) |

固定パターンが無い条件では**単純平均が理論上の最小分散**になり、棄却を行う手法は
有効なサンプルまで捨てる分だけ必ず不利になります。ただし劣化量には差があります。

- **3(ウィンザライズ)の劣化は 0.2〜0.3% しかありません。** 値を捨てずに境界へ丸める
  (Winsorize)ため情報の損失が小さいからです
- 2(シグマクリップ)の劣化は 1.0〜1.5% で、3 の約5倍です

**結論: ダーク減算を使う場合は 3 を選んでください。** 単純平均とほぼ同じ低ノイズを
保ちながら、飛行機や宇宙線のような突発的な写り込みにも備えられます。
ダーク減算を使わない場合は、固定パターンにもある程度対処できる 2 が無難です。

対話画面では、ダーク減算を有効にすると「3 がおすすめです」と表示されます。

### ⚠ 4番(dpc・欠陥画素補正)のトレードオフ

センサーの欠陥画素は**毎コマ同じ位置で同じように明るい**ため、コマ間のばらつきを
見るシグマクリップでは原理的に除去できません(1〜3ではどうしても残ります)。

4番(dpc)は、コマ間ではなく**同じ画像内の周囲の同色画素**と比べて突出した画素を
中央値で置き換えます。実測(45MP・64コマ)で孤立した白点の約57%を除去できました。

**ただし、これは「周囲から突出した画素を消す」処理です。**
星・遠くの街灯・金属の小さな反射など、**本当に1画素しかない明るい被写体も
一緒に消えてしまいます**(いわゆる星食い現象)。暗部は綺麗になりますが、
細かい構造を壊すリスクがあることを承知の上でお使いください。

**固定パターンを確実に、かつ細部を一切損なわずに消したいならダーク減算を使ってください。**
それが本来の対処法で、4番(dpc)はダークフレームが用意できないときの次善策です。

補正の強さは iniの `hot_pixel_threshold` で調整できます(小さいほど強い)。

| しきい値 | 白点の除去率 | 明部で書き換わる画素 |
|---|---|---|
| 12.0 | 45% | 0.03% |
| **8.0**(既定) | **57%** | **0.13%** |
| 6.0 | 67% | 0.31% |

### アルゴリズムの中身

**2. シグマクリップ** — 各画素について全コマの平均と標準偏差を求め、
±3σから外れた値を捨てて平均を取り直します。変化が無くなるまで繰り返します。

**3. ウィンザライズ** — 天体写真のスタックで実績のある
*Winsorized Sigma Clipping* に、MADによる頑健な初期推定を組み合わせたものです。

1. **中央値とMAD**(中央絶対偏差)で中心と散らばりを推定します。
   平均と標準偏差は外れ値そのものに引っ張られますが、中央値とMADは
   引っ張られません
2. 範囲外の値を**捨てずに境界値へ丸め**(Winsorize)ながら、中心と散らばりを
   更新します。値を捨てないので情報の損失が小さく、上の実測でも劣化 0.2% に
   とどまっています
3. 収束後、最終的な範囲から外れた値だけを捨てて平均します

**4. ウィンザライズ＋欠陥画素補正(dpc)** — 3 の結果に対し、周囲8点(Bayerなので±2画素)の
中央値とMADで判定し、突出した画素を中央値で置き換えます。欠陥は隣り合って
出ることがあるため2点までは道連れを許容し、周囲すべてより外れている画素は
欠陥の確度が高いので基準を半分に緩めます。

### ⚠ 枚数が少ないとシグマクリップは効きません

n枚の標本では、平均からのずれは最大でも **(n-1)/√n σ** にしかなりません。
しきい値がこれ以上だと、**理論上1つも棄却が起きません**。

| 枚数 | 棄却可能な上限 | 3σで効くか |
|---|---|---|
| 6枚 | 2.04σ | ✗ 効かない |
| 10枚 | 2.85σ | ✗ ほぼ効かない |
| 12枚 | 3.18σ | △ わずかに |
| 32枚 | 5.48σ | ○ |
| 64枚 | 7.88σ | ○ |

本ツールはこの状態を検出して警告を出します。**枚数を増やす**か、
iniの `sigma_low` / `sigma_high` を下げてください。
なお 3・4 はMADを使うため、この制限を受けにくくなっています。



## ダーク減算

ダークフレーム(レンズにフタをして、同じ露出時間・同じ温度で撮ったコマ)を
引くと、熱ノイズや常時光る画素(ホットピクセル)を取り除けます。

### 与え方は2通り

**1. キーワードで自動的に拾う**(`--dark keyword`)

グループフォルダの中から、次のどちらかを自動で探します。

- ファイル名に `_DARK` を含むDNG … 例: `DSC0100_DARK.dng`
- `_DARK` を名前に含むサブフォルダの中のDNG … 例: `_DARK\DSC0100.dng`

見つかったファイルは明フレームからは除外されます。
複数見つかった場合は**平均してから**使います(ダーク自体のノイズを持ち込まないため)。

キーワードはiniの `[dark] keyword` で変更できます。

**2. 1枚を指定する**(`--dark file`)

フルパスで指定した1枚を、すべてのグループに共通で使います。
あらかじめ作ったマスターダークを使う場合に便利です。

### 計算内容

```
出力 = 明フレーム − ダークフレーム + ブラックレベル
```

明もダークも黒レベルを含んでいるため、単純に引くと黒レベルまで消えてしまいます。
DNGの `BlackLevel` タグは「このデータの黒は N である」と宣言したままなので、
そのぶんを足し戻さないと現像ソフトが黒を二重に引いてしまいます。

黒レベルはCFAの位置ごとに異なりうるため、`BlackLevelRepeatDim` の
繰り返しパターンに従って位置ごとの値を足し戻します。

## 位置合わせ(手ぶれ補正)

三脚を使わない連写では、コマごとに数画素の並進ずれが出ます。
そのまま加算平均すると細部が溶けてしまうため、基準コマ(1枚目)に重なるよう
各コマを平行移動してから合成します。

`--align` を付けるか、iniの `[align] enabled = true` で有効になります。**既定はOFF**です。

### ⚠ 有効にすると出力がリニアDNGになります

Bayerモザイクのままサブピクセル移動すると、隣り合う画素が別の色になってしまい
色の並びが壊れます。そのため位置合わせを行うときは、**先にデモザイクしてから**
合わせて合成します。結果として:

| | 位置合わせOFF(既定) | 位置合わせON |
|---|---|---|
| 出力形式 | Bayerモザイクのまま(通常のDNG) | リニアDNG(デモザイク済み) |
| 1画素あたり | 1サンプル | 3サンプル(RGB) |
| 一時ファイル | 45MP×64枚で約5.9GB | 約17.6GB(**約3倍**) |
| 現像ソフト側 | 通常のRAWとして扱われる | デモザイク済みとして扱われる |
| 処理時間 | 短い | デモザイクのぶん長い |

ずれていない素材(三脚・リモートレリーズ)では、**OFFのままが最高画質**です。
デモザイクを挟まないぶん、現像ソフト側の最新のデモザイク処理をそのまま使えます。

### 補正できるもの・できないもの

補正するのは**平行移動だけ**です。回転・拡大は補正しません。
連写の短い時間内では並進が支配的で、回転まで推定するとコストが跳ね上がる
わりに得るものが少ないためです。

(レンズの歪曲収差・倍率色収差は別枠で選べます。下の
[収差補正](#収差補正)を参照してください。)

### 自動モードとマニュアルモード

| モード | 使いどころ |
|---|---|
| `auto`(既定) | 画像からずれ量を推定する。通常はこちら |
| `manual` | ずれ量を自分で決めたい場合。iniに書いた値をそのまま使う |

マニュアルモードは iniの `[align.manual]` に、**DNGのフルパスとシフト量**を
並べて指定します。

```ini
[align]
enabled = true
mode = manual

[align.manual]
D:\shoot\burst01\DSC0002.dng = 1.2, -0.4
D:\shoot\burst01\DSC0003.dng = 2.5, -0.9
```

- `x, y` は**その画像を動かす量**[px]です。`x > 0` で右へ、`y > 0` で下へ動きます
- **0.1px 刻み**での指定を想定しています
- ここに書かなかったファイルは動かしません(基準にしたいコマは書かなければOK)
- パスの大文字小文字は区別しません。一致しなかった指定は実行前に警告として
  一覧表示されるので、書き間違いはすぐ分かります

### 推定の手順(自動モード)

1. 輝度画像(`0.25R + 0.5G + 0.25B`)を1/8に縮小し、`±max_shift/8` を総当たりして
   大まかな位置を掴む(全解像度で総当たりすると45MP×数千通りで実用になりません)
2. 全解像度で、その周り±5画素を間引いた画素だけで探し直す
3. 残差の最小点とその両隣に放物線を当てはめ、サブピクセル位置を求める
4. その結果を初期値に、基準画像の勾配から並進量を解き直して詰める

4番目が要点です。3番目の放物線フィットだけでは、細かい模様の多い画像で
0.2画素ほどの偏りが残ります。勾配から解き直すことでこの偏りが取れ、
`tests/test_alignment.exe` の合成テスト画像では**残差 0.01画素以下**まで詰まりました。

実写では被写体の動き・ノイズ・レンズの収差が加わるため、この数値がそのまま
出るわけではありません。合成データでの推定器の素性を示す値としてお読みください。

移動そのものはバイリニア補間で行い、画像の外を参照する場合はいちばん近い端の
画素を使います(外周が引き伸ばされますが、平均する枚数ぶんの端数画素です)。

### 探索範囲を超えた場合

`max_shift`(既定64px)より大きくずれたコマは合わせきれません。
その場合は処理後に警告が出るので、iniの `[align] max_shift` を大きくしてください。

### 収差補正

位置合わせを使うとデモザイクを挟むため、その時点でDNGに入っている
**レンズ補正命令(オペコード)**を適用できます。Bayerのまま平均する経路では
デモザイクをしないので適用されません。**位置合わせのON/OFFで絵の作りが
変わらないよう、既定はすべてOFF**にしてあります。

| ini (`[align]`) | 内容 | 既定 |
|---|---|---|
| `distortion` | 歪曲収差(たる型・糸巻き型のゆがみ) | `false` |
| `lateral_ca` | 倍率色収差(周辺での色ズレ) | `false` |
| `vignette` | 周辺光量落ち | `false` |

コマンドラインからは `--correct distortion,lateral_ca` のようにカンマ区切りで
並べます(`--correct none` で全部OFF)。

**倍率色収差だけを補正するのは筋の通った選び方です。** 倍率色収差は
「色ごとに像の大きさが違う」というズレなので、直さないまま重ねると、その差が
平均結果に固定されてしまいます。歪曲収差は像全体が同じように動くだけなので、
重ねてから現像ソフト側で直しても結果は変わりません。

> **実装メモ**: DNGでは歪曲収差と倍率色収差が `WarpRectilinear` という
> **1つのオペコードに同居**しています(色プレーンごとの係数を持ち、その共通成分が
> 歪曲、色ごとの差が倍率色収差)。片方だけを選んだ場合は、緑を基準プレーンとして
> 係数を組み替えて分離しています。`tests/compare_dng.exe` で確認すると、
> 倍率色収差のみを選んだときは緑プレーンがほぼ無変化(平均差 1.5)のまま
> 赤・青だけが動く(平均差 41)ことが確かめられます。

## 設定ファイル(.ini)

exeと同じ場所の `DNG Multi Frame Averager.ini` を書き換えると、
**次回起動時の既定値**が変わります。対話画面では、その値が最初から
選ばれた状態になります(コマンドライン引数の方が優先されます)。

初回起動時に、説明コメント付きのファイルが自動生成されます。

```ini
[output]
suffix = _AVE
mode = subfolder          ; subfolder | parent
uncompressed = false

[dark]
mode = none               ; none | keyword | file
keyword = _DARK
;file = D:\darks\master_dark.dng

[stack]
method = winsor           ; mean | sigma | winsor | dpc | all
sigma_low = 3.0
sigma_high = 3.0
max_iterations = 5
hot_pixel_fix = auto      ; auto(手法4 dpc のみ) | always | off
hot_pixel_threshold = 8.0

[align]
enabled = false           ; 位置合わせ。ONにすると出力はリニアDNG
mode = auto               ; auto | manual
max_shift = 64            ; auto のときに探索する最大のずれ量[px]
subpixel = true           ; auto のときに画素より細かく合わせるか
distortion = false        ; 歪曲収差を補正するか
lateral_ca = false        ; 倍率色収差を補正するか
vignette = false          ; 周辺光量落ちを補正するか

[align.manual]
; mode = manual のときの、ファイルごとのシフト量(画像を動かす量[px])
;D:\shoot\burst01\DSC0002.dng = 1.2, -0.4

[advanced]
band_memory_mb = 512      ; 帯域処理に使うメモリの目安
noise_sample_stride = 16  ; ノイズ推定の画素間引き
exit_countdown_sec = 3
```

## 出力されるDNGについて

- **画素データ**: 選んだアルゴリズムでの合成結果を四捨五入した値。
  ビット深度は入力に一致
- **メタデータ / プレビュー**: グループ1枚目のDNG由来
- **圧縮**: 既定はロスレス圧縮(画素値は完全に保たれます)
- **内部整合性タグ**: `NewRawImageDigest` / `RawDataUniqueID` は合成後の画素データに
  対して**正しく再計算**されます

最後の点が重要です。DNGには「画素データのMD5ダイジェスト」が記録されており、
Adobe Camera Rawはこれを画素データと照合します。食い違うと
「ファイルが破損している可能性があります」と警告されます。

本ツールは元ファイルのバイト列を切り貼りするのではなく、**Adobe DNG SDKに
DNGを新規ファイルとして書き出させる**ため、これらのタグが自動的に正しく再計算されます。

## トラブルシューティング

| メッセージ | 原因 | 対処 |
|---|---|---|
| `処理できるDNGが見つかりません` | フォルダにDNGが無い | フォルダの中、または直下のサブフォルダにDNGを置く |
| `枚数が少なく、±3.0σでは棄却が起きません` | 枚数に対してしきい値が大きい | 枚数を増やすか、iniの `sigma_low`/`sigma_high` を下げる |
| `1枚目と仕様が違います` | サイズ/ビット深度/Bayerパターンが不一致 | 同一カメラ・同一設定で撮影したファイルのみをまとめる |
| `DNGが1枚だけで平均できません` | グループ内のDNGが1枚 | 2枚以上を同じフォルダに入れる |
| `ダークフレームの仕様が明フレームと違います` | ダークと明のサイズ等が不一致 | 同じカメラ・同じ設定で撮ったダークを使う |
| `16bitを超えるBayerデータには対応していません` | 32bit RAW | 対象外です |
| `一時ファイルを作成できませんでした` | 一時フォルダの空き容量不足 | 空き容量を確保する(枚数×画素数×2バイト必要) |
| `メモリが不足しました` | 画素数が非常に大きい | iniの `band_memory_mb` を下げる |

## 既知の制限事項

- **位置合わせは既定でOFFです。** OFFのまま連写中にカメラが動くと、その分だけ結果が
  甘くなります。三脚固定＋リモートレリーズ(またはセルフタイマー)での撮影が最良ですが、
  手持ちの場合は位置合わせを有効にしてください。
- **位置合わせで補正できるのは平行移動だけです。** 回転・拡大は補正しません。
- **位置合わせを有効にすると出力はリニアDNGになります。** 一時ファイルも約3倍に
  なります(詳細は[位置合わせ](#位置合わせ手ぶれ補正))。
- **画素値は8/16bit整数のみ対応**です。浮動小数点DNGは対象外で、
  明確なエラーメッセージを出してスキップします。
- **プレビューは1枚目のものをそのまま引き継ぎます。** 合成でノイズが
  減るぶん、プレビューは実際の画素より僅かにノイジーですが、表示用途では問題ありません。
  DNG 1.7以降のJPEG XL圧縮プレビューは本ビルドではデコードできないため引き継がれません。
- **一時ファイルを使います。** 処理中、システムの一時フォルダに
  `枚数 × サンプル数 × 2バイト` の作業ファイルを作ります(64枚×45MPで約5.9GB、
  位置合わせONなら約17.6GB)。
  処理終了時に自動削除されますが、空き容量が必要です。
- 対応OSは **Windowsのみ**です。
